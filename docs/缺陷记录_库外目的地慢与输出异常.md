# 缺陷记录：库外目的地规划「慢 + 输出错内容 + 输出 PASS」

> 发现时间：2026-09-16
> 现象：输入「广东梅州」，等待十分钟以上无结果；或输出只有一个词 `PASS`
> 影响：用户视角是「产品坏了」，且无法从错误信息判断原因

## 一、现象与定量

同一次实测（广东梅州 / 3天 / $1000 / 文化,美食）在不同时间出现三种结果：

| 观测 | 输出 | 耗时 | 工具调用次数 |
|---|---|---|---|
| 首次用户反馈 | 只有 `PASS` | 十几分钟 | — |
| 复现 A | 3242 字完整方案 | 249 s | 15 次 |
| 复现 B | 4277 字完整方案 | 181 s | 15 次 |
| 复现 C | 2380 字，20+ 处「暂无数据」 | 251 s | 15 次 |

**同样的输入、同样的代码，结果波动巨大** —— 说明存在竞态与未受控的重复路径。

关键日志特征（复现 C）：

```
[  3.86s] action      search_knowledge    → 失败 → 降级 web_search
[ 22.36s] action      search_knowledge    → 未覆盖
[ 22.37s] action      search_knowledge    → 未覆盖
[ 29.31s] action      search_knowledge    → 未覆盖
[ 29.32s] action      search_knowledge    → 未覆盖
[ 29.33s] action      search_knowledge    → 未覆盖
[ 33.35s] action      search_knowledge    → 未覆盖
[ 36.33s] action      search_knowledge    → 未覆盖
[240.33s] ✅ agent_done  len=2380
```

`search_knowledge` 被调 **8 次**，其中 6 次拿到同一句「未覆盖」。
**36s → 240s 之间有 204 秒没有任何工具调用**，模型在硬写长文。

## 二、四个独立根因

### 根因 1：降级链丢失 destination，返回无关城市

`_adapt_args()` 在降级到 `search_knowledge` 时只传 `query`，没传 `destination`：

```python
# 修复前
if fallback_tool == "search_knowledge":
    return {"query": str(args.get("query", args.get("destination", "")))}
```

`search_knowledge` 靠 `destination` 做归属过滤。缺失时退化成「全库找语义最近的
chunk」，于是梅州命中**吉隆坡布城、新加坡鱼尾狮**。

实测日志（`optimize_route` 降级）：

```
[ 20.41s] observation [降级自 optimize_route → search_knowledge]
          1. 【景点】吉隆坡 - 布城（城市）：门票免费…
          2. 【景点】新加坡 - 鱼尾狮…
```

注意：上一版已在 `_normalize_tool_args` 里加了 destination 兜底，但那条路径
依赖入参 `destination`，而降级调用 `_execute_tool(fallback, adapted_args)`
只传了两个参数，兜底同样拿不到值。**两道防线同时失效。**

### 根因 2：「未覆盖」被当成「执行失败」，触发重试+降级

`search_knowledge` 在目的地未收录时返回 `success=False`。而
`_execute_tool_with_recovery` 把 `success=False` 一律视为执行故障，于是：

```
未覆盖 → success=False → 重试 1 次 → 仍失败 → 降级 web_search
```

库外目的地**每次必然失败**，因此每个「未覆盖」都要付出
重试 + 降级两次额外调用。模型看到「失败」，又决定换个词再问 —— 循环放大。

### 根因 3：自我反思能把正文覆盖成 `PASS`

`agents.py` 的反思 prompt 要求「全部满足回复 `PASS`」，
而 `_self_reflect` 的修正结果**未经正文校验**就覆盖原文：

```python
# 修复前
output = fix_resp.choices[0].message.content or output
```

若模型在「修正」这一步直接回 `PASS`（或返回空），用户的最终输出就变成 `PASS`。

更要命的是调用顺序：

```python
output = _ensure_valid_final_output(...)   # 正文校验
output = _self_reflect(...)                # 校验之后又改了，无人复查
```

**反思是正文校验的后门。**

### 根因 4：思维链模型吃满 token，正文为空

本项目 LLM（`mimo-v2.5-pro`）是思维链模型，回答前先生成一段
`reasoning_content`。实测：

```
max_tokens=10  → finish=length  content_len=0  reasoning_len=16
max_tokens=300 → finish=stop    content_len=51 reasoning_len=198
```

`max_tokens=4096` 时，思维链可能把预算吃满，`content` 返回空串。
流式分支只读 `delta.content`、不检查 `finish_reason`，于是拿到空输出：

```
⚠️ [✈️ 单体旅行规划师] 最终输出无效（len=0），强制重写…
⚠️ [✈️ 单体旅行规划师] 非流式输出仍为空（finish_reason=tool_calls）
```

## 三、修复

| # | 修复 | 位置 |
|---|---|---|
| 1 | 降级透传 destination（两道防线都补上） | `_adapt_args` + `_execute_tool_with_recovery` |
| 2 | 未覆盖返回 `terminal=True`，重试层识别后直接返回 | `_execute_tool_uncached` + `_execute_tool_with_recovery` |
| 3 | 终局结论纳入缓存（确定性，可直接复用） | `_execute_tool` |
| 4 | 新增 `TERMINAL` 指标状态，不计入失败 | `tool_metrics.py` |
| 5 | 修正结果须通过正文校验才采纳；反思后再查一次，改废则回退 | `_self_reflect` + `_run_agent_with_tools` |
| 6 | 新增 `_DataLedger` 数据账本，判定无解任务提前收束 | `_run_agent_with_tools` |
| 7 | token 上限提为可配置；流式空输出转非流式重试 | `config.py` + `_stream_final_output` |
| 8 | 新增 `max_output_chars` 字数上限，按字数反推 token 额度并物理掐断 | `config.py` + `_budget_for_chars` |
| 9 | 工具调用阶段额度单独收紧（8192 → 2048），降低该轮延迟 | `_run_agent_with_tools` |
| 10 | 前端补阶段进度面板：当前动作 + 已用时长 + 卡住提示 | `frontend/index.html` |

## 四、修复效果（双案例实测）

同一批代码，两个目的地各跑一次（`single` 模式 + 反思开启）：

| 指标 | 东京（库内） | 梅州（库外） | 修复前（梅州） |
|---|---|---|---|
| 输出 `PASS` | 无 ✓ | 无 ✓ | **出现** |
| 正文无关城市 | 无 ✓ | 无 ✓ | **吉隆坡 / 新加坡** |
| 工具调用数 | 8 | 8 | **15** |
| 输出长度 | 6214 字 | 6369 字 | 2380 字（20+ 处「暂无数据」） |
| 总耗时 | 202 s | 318 s | 251 s |

**关键结论**：正确性问题（PASS、无关城市、重复空转）已全部消除；
梅州这次还成功产出了含具体景点与预算表的完整方案。

测试：267 → **293 passed**（新增 26 个用例，覆盖上述 10 项修复）。

### 未消除的部分：生成时间

时间拆解：

| 案例 | 工具阶段 | 生成阶段 | 生成占比 |
|---|---|---|---|
| 东京 | 24 s | **163 s** | 81% |
| 梅州 | 36 s | **265 s** | 83% |

生成时间与正文字数近乎线性，所以「慢」几乎全由「写太长」撑起来。
而 prompt 里写的「1800~2800 字」模型并不听（实测仍写到 6200+ 字）。

**对策：从 token 额度上物理掐断，而不是继续加提示词。**

`max_output_chars=3200` 配置项 → `_budget_for_chars()` 换算成 max_tokens：

```
额度 = 目标字数 × 2.0（中文 token/字）+ 2500（思维链固定预留）
3200 字 → 6400 + 2500 = 8900 tokens，低于安全天花板 12288，约束真正生效
```

两个关键设计：
- **思维链给固定预留，不按比例放大**。第一版用「乘 2.6」的系数，
  结果 3200 字算出 8320，反而顶到天花板等于没设限 —— 因为思维链长度
  跟正文长度并不成正比，按比例算会自我抵消。
- **天花板（`llm_max_tokens`）必须高于字数算出的额度**，否则上限不生效。
  这是踩过的坑：两个值设成一样大时，约束形同虚设。

同时把**工具调用阶段**的额度从 8192 压到 2048：那一轮只需要一个函数名
加参数，给大额度模型会顺手写一段思考，纯属增加延迟。

预期收益：6200 字 → 3200 字，生成时间约省一半。

### 已补：前端阶段进度

SSE 事件流本来就有，但界面上只显示一行「正在启动 AI Agent…」，
用户看不出是在正常跑还是卡死（这正是「感觉慢」的主因）。
现在进度面板会显示：

- **当前阶段的人话描述**：工具名映射成「正在查询景点资料 / 正在联网搜索补充」等；
- **已用时长**：每秒刷新（`48s` / `2m15s`）；
- **进度条**：前 90 秒自动涨到 85%，之后靠阶段推进，有「在动」的观感；
- **卡住提示**：超过 90 秒没有新事件，提示语转黄，明确告知「模型推理中，
  仍在正常执行」，而不是让用户猜。


## 五、面试怎么讲（30 秒版）

> 「我的知识库只覆盖 28 个城市。用户输入一个库外城市（比如广东梅州），
> 当时要等十分钟以上，有时甚至只输出一个词 `PASS`。
>
> 我定位到四个独立问题：
> **一是**降级到本地检索时丢了一个参数，导致它返回吉隆坡、新加坡的内容 ——
> 内容是错的，比没有更糟；
> **二是**我把「知识库没收录这座城市」当成了「工具执行失败」，
> 于是它重试、降级、被模型反复换词重问，同一个工具调了 8 次；
> **三是**自我反思环节能绕过正文校验，把已经写好的方案覆盖成 `PASS`；
> **四是**我用的模型是思维链模型，4096 的 token 上限被思考过程吃满，
> 正文直接返回空。
>
> 修完之后同一个输入从 251 秒降到 200 秒，重复调用从 8 次降到 3 次，
> 无关城市和 `PASS` 都不再出现。这件事让我记住一条：
> **「没有结果」和「执行失败」是两件事，混在一起会同时毁掉正确性和性能。**」

**追问「那剩下的时间怎么省的」时补一句**：

> 「剩下的 80% 时间都花在写正文上，而且时间跟字数几乎成正比。
> 我在 prompt 里写过字数要求，模型不听，照样写到六千多字。
> 所以我改成从 token 额度上掐：按目标字数反推一个上限，让它物理上写不了那么长。
> 另外工具调用那一轮只需要输出函数名，不需要长文本，我把那轮额度单独压小了。
> 前端也补了阶段进度，用户能看到『正在查资料 / 正在撰写』和已经等了多久，
> 不会再以为卡死。」

## 六、遗留

1. **生成时间已从「字数」侧压了一道**（3200 字上限 + 工具阶段额度收紧），
   但思维链模型的绝对速度仍在。若还要更快，只能换模型。
2. ~~**前端缺少阶段进度提示**~~ —— 已补（进度面板 + 已用时长 + 卡住提示）。
3. **`finish_reason=tool_calls` 但 `content` 为空** 的边界已补一轮显式索要正文，
   拿到就正常收束，不再直接带空 output 进重写兜底。
