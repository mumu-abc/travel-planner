# 缺陷记录：库外目的地触发「检索静默失败」

> 发现日期：2026-09-16　·　严重度：**高**
> 状态：**已修复（A 档 + B 档）并验证**
> 复现脚本：`scripts/probe_retrieval.py`
> 回归测试：`tests/test_crew_enhanced.py` → `TestFallbackPlan::test_fallback_plan_out_of_domain_has_no_foreign_cities`
> 　　　　　`tests/test_pipeline_and_retrieval.py` → `TestOutOfDomainRetrieval`

---

## 1. 一句话定性

**这不是模型幻觉，是检索层的 out-of-domain 无拒答（silent retrieval failure）。**

知识库里没有目标城市时，检索器不会说"没有"，而是返回语义上最接近的 k 条内容。
这些内容**全部为真**，但**与查询完全无关**。

## 2. 现象

输入「梅州五华」，输出标题是《梅州五华 3日旅行攻略（离线版）》，正文却是：

```
📍 目的地信息
1. 【餐厅】吉隆坡 - 黄亚华小食店（华人菜）：人均MYR20-40，必点烧鸡翅
2. 【预算】孟买 - 经济：$20-35/天 | 舒适：$50-100/天 | 豪华：$300+/天
3. 【景点】布宜诺斯艾利斯 - 五月广场（历史）：门票免费，游览1小时
4. 【预算】吉隆坡 - 经济：$25-45/天 | 舒适：$50-100/天 | 豪华：$200+/天
5. 【餐厅】吉隆坡 - 新峰肉骨茶（华人菜）：人均MYR20-35
```

同一份输出里，路线 / 预算 / 天气三段**反而是正确报错的**：

```
🗺️ 路线规划   未找到 梅州五华 的景点数据
💰 预算规划   无法生成预算方案。
🌤️ 天气信息   [天气数据获取失败: 未找到城市坐标: 梅州五华]
```

→ **只有检索段在"硬凑答案"，算法段都诚实地说了"没有"。** 这个反差本身就是定位线索。

## 3. 为什么比幻觉更危险

| | 幻觉 | 本缺陷 |
|---|---|---|
| 内容真假 | 编造，不存在 | **全部为真** |
| 与查询相关性 | 通常相关但细节错 | **完全无关** |
| 能否肉眼识别 | 容易（编的地名一眼假） | **很难**（每条都经得起查） |
| 评测能否抓到 | 事实一致性检查可抓 | **抓不到**（没有假事实） |

打个比方：去图书馆问"有没有梅州五华的旅游书"，管理员没找到，却不说"没有"，
而是从书架上抓了 5 本"看起来也是讲旅游的"递给你——一本讲马来西亚，一本讲印度，一本讲阿根廷。

## 4. 复现

```bash
python scripts/probe_retrieval.py
```

脚本会打印知识库全部目的地、目标城市是否存在，以及两组查询的 top-5 命中情况。

## 5. 实测数据

知识库共 **28** 个目的地：

```
东京 伊斯坦布尔 伦敦 吉隆坡 墨尔本 孟买 巴厘岛 巴黎 布宜诺斯艾利斯 布拉格
开罗 悉尼 成都 新加坡 旧金山 曼谷 柏林 洛杉矶 清迈 纽约 维也纳 罗马
迪拜 里约热内卢 阿姆斯特丹 首尔 香港 马尔代夫
```

**中国大陆只有成都。没有梅州、五华。**

| 查询 | top-5 归属 | 命中率 | 最高分 |
|---|---|---|---|
| 东京 | 东京 ×5 | **5 / 5** | 0.6779 |
| 梅州五华 | 吉隆坡 ×3、孟买 ×1、布宜诺斯艾利斯 ×1 | **0 / 5** | 0.5603 |

关键观察：**两条查询的最高分只差 0.12**（0.68 vs 0.56）。

## 6. 根因（两处叠加，缺一不可）

**① 检索器不会说"没有"**

`search_knowledge()`（`app/tools/knowledge_search.py`）内部用 FAISS `IndexFlatIP` 做
kNN 检索，语义上是"找出最像的 k 条"——**它没有"都不像"这个输出**。
整个函数**没有任何相关性阈值或归属校验**，`ranked` 排序后直接取前 k 条返回。

**② 离线兜底漏传了目的地过滤参数**

`_generate_fallback_plan()`（`app/crew.py`）里的检索调用是：

```python
results = search_knowledge(query=destination, top_k=10)
```

**没有传 `destination=`**。而 `search_knowledge()` 里那道归属过滤是依靠这个参数生效的：

```python
if destination and destination not in chunk["destination"] and ...:
    continue
```

参数没传 → 过滤不生效 → 库外查询直接把 top-10 原样吐出，中间没有任何"这不是你要的城市"的判断。

## 7. 影响面

| 路径 | 是否受影响 | 说明 |
|---|---|---|
| **离线兜底** `_generate_fallback_plan` | ✅ 确认受影响 | 漏传 `destination`，100% 复现 |
| **在线 Agent 工具调用** | ⚠️ 有条件受影响 | 工具包装里是 `arguments.get("destination")`，**可填可不填**；只要 LLM 漏传这个参数，同样的坑照样踩 |

→ 所以这不是单点 bug，是**检索层缺少"拒答"能力**，兜底函数只是第一个暴露点。

## 8. 修复方案

### A 档：补上漏传的参数（一行，零风险）

`_generate_fallback_plan` 的检索调用补 `destination=destination`。

- 效果：库外查询时过滤后结果为空 → 打印「（知识库暂无数据）」，问题消失
- 代价：无。不动核心逻辑，不影响任何评测指标
- 覆盖：仅离线兜底路径

### B 档：检索层加「目的地覆盖校验」（推荐，治本）

在 `search_knowledge()` 里加一个**前置检查**：

```
如果传了 destination，而它不在 DESTINATIONS 里
  → 直接返回空，并给出可区分的原因："知识库未覆盖该目的地"
```

比事后过滤更早、更省算力，而且能让上层区分两种空结果：

- `not_covered`　知识库没有这个城市　→ 应提示用户换城市 / 走联网搜索
- `no_match`　　城市有，但这几条不相关　→ 正常空结果

同时把工具 schema 里的 `destination` 改成**必填**，防止 LLM 漏传。

- 效果：离线 + 在线两条路径全部受益
- 代价：会改变检索相关评测数字，**需要重跑评测并更新 README**

### C 档：产品层文案（体验优化）

库外目的地时明确提示「知识库暂未覆盖 XX，建议换个城市，或开启联网搜索」，
而不是只给一句轻描淡写的"仅供参考"。

### ❌ 明确不推荐：加一个绝对分数阈值

最直觉的想法是"分数低于 X 就丢弃"，但实测**行不通**：

- 不相关最高分 0.56，相关最高分 0.68，**只差 0.12**
- 阈值卡 0.60 在这两个样本上勉强能分，但 n=2 完全不足以标定
- 不同查询的分数分布差异很大，固定阈值必然误伤

→ 结论：**用确定性判据（目的地归属），不要用需要标定的阈值。**

## 9. 推荐顺序

**先 A，再 B，C 可选。**

1. **A 立刻做**——一行改动止血，零风险，当天就修了
2. **B 接着做**——治本，覆盖在线路径；做完重跑一次检索评测，把新数字更新进 README
3. **C 看时间**——纯体验优化，不影响正确性

## 10. 修复进度

### A 档 —— 已完成（2026-09-16）

改动：`_generate_fallback_plan()` 的检索调用补上 `destination=destination`，
并在结果为空时输出明确原因，而不是像原来那样静默跳过这一节。

验证（离线兜底的「目的地信息」一节）：

| 目的地 | 修复前 | 修复后 |
|---|---|---|
| 梅州五华 | 吉隆坡 ×3、孟买 ×1、布宜诺斯艾利斯 ×1 | （知识库暂未覆盖「梅州五华」，无可用基础信息） |
| 东京 | 东京 ×5 | 东京 ×5　← 无回归 |

回归测试：`tests/test_crew_enhanced.py` 新增
`test_fallback_plan_out_of_domain_has_no_foreign_cities`
——断言库外查询的输出里不得出现其它城市名，且必须含「暂未覆盖」。

> 该测试**不 mock 检索**，走真实 `search_knowledge`，所以修复前必然失败：
> 修复前 probe 实测就是 0/5 命中、命中内容正是吉隆坡 / 孟买 / 布宜诺斯艾利斯。

测试结论：`5 passed`（含 4 个既有 fallback 测试，均无回归）。

### B 档 —— 已完成（2026-09-16）

三处改动：

1. **检索入口加覆盖校验**（`is_destination_covered()`）
   传了 `destination` 但知识库没有该城市 → **跳过向量 / BM25 检索**，直接返回空。
   顺带省掉了模型加载和 FAISS 查询的开销。
   ⚠️ 特意保留了用户上传文档的检索通道：库外城市仍可能命中用户自己导入的资料。

2. **调用侧参数兜底**（`_normalize_tool_args()`）
   `search_knowledge` 缺 `destination` 时用本次规划的目的地自动补上，
   保证归属过滤永远有值 —— 这是挡住「LLM 漏传」的那一道。

3. **文案区分两种空结果**（`_execute_tool()`）
   - `未覆盖`　知识库没有这个城市 → 提示改用 web_search 或换城市
   - `没查到`　城市有，这次没命中 → 原有文案

   顺带把工具 schema 里 `search_knowledge` 的 `destination` 从可选改为**必填**。

验证：

| 检查项 | 结果 |
|---|---|
| 库外（传 destination） | 返回 **0 条**，不再硬凑 |
| 库内（东京，传 destination） | 返回 5 条，**全部是东京**，无回归 |
| 不传 destination | 仍正常返回 —— 兼容既有调用，未被误伤 |
| LLM 漏传 destination | 自动补成「梅州五华」 |
| 文案 | 「知识库未覆盖「梅州五华」…建议改用 web_search」 |

回归测试：`tests/test_pipeline_and_retrieval.py` → `TestOutOfDomainRetrieval`（6 个用例）。
**全量测试：257 passed。**
