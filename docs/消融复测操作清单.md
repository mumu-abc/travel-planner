## 第 2 步：正式跑 3 case（约 1 小时）

```bash
python -m eval.eval_runner --cases 3 --ablation --output eval/report_ablation.md
```

Windows 也可以用封装好的脚本（会自动挑一个装了依赖的 Python，并先做配额自检）：

```powershell

```

**跑的过程中**：

- 会打印预计耗时，4 个变体 × 3 case = 12 次生成
- 每跑完一个变体就写一次 `eval/report_ablation.partial.md`，**随时 Ctrl+C 不丢已完成部分**
- 顺序是：multi → single → sequential → multi 无反思

**预计时间**：约 40–80 分钟，取决于 API 响应速度。别让电脑休眠。

## 第 3 步：读结果（重点只看两个数）

打开 `eval/report_ablation.md`，只看「关键结论」那一节：

```
multi vs single 平均分差：+X.X   ← 第 1 个关键数
```

| 分差 | 含义 | 简历该怎么写 |
|---|---|---|
| **−5 ~ +5** | 质量打平 | 「3 case 上 multi 与 single 质量无显著差异（分差 X），但 multi 慢 Y 倍、贵 Z 倍，故默认档选 single」← **大概率是这个** |
| **> +5** | multi 确实更好 | 「multi 平均分高 X 分，但成本 Y 倍；在要求五板块齐全的深度档启用」 |
| **< −5** | multi 反而更差 | 「3 case 上 multi 不及 single，已将其降级为实验档」 |

然后看**波动 σ**：如果 σ 比分差还大，说明结论不稳定，简历上就只能说「未观察到显著差异」，
**不能**说「谁更好」。

## 常见坑（按顺序排查）

**1. 提示找不到 / 缺 faiss、pulp**
说明你用的 python 没装依赖。用这个绝对路径：
`C:\Users\钟利林\.workbuddy\binaries\python\envs\default\Scripts\python.exe`

**2. 跑一半报 429**
配额中途又烧完了。看 `eval/report_ablation.partial.md`，已完成的配置是有效的；
等配额恢复后重跑，或者只跑剩下的配置。

**3. 某个配置「成功 0/3」**
这是评测器在正常工作——它把降级的 run 隔离掉了，正是为了避免污染结论。
看报告底部的「失败与降级明细」，那里写了原因。

**4. 分数全是 0 但状态 ok**
**立刻停下**，这是 bug，别拿去面试。找我修。
