## L0 · 必背（10 题，不会就别去面试）

### 1. 什么是 Agent？和 Workflow 的区别？
**背**：Agent = LLM + 工具 + 自主决策循环，**由模型决定下一步做什么**；
Workflow = 人写死的 DAG，步骤和分支提前定好。
判据：**控制流在代码里还是模型里**。

**追问**：什么时候不该用 Agent？
→ 流程固定、要求稳定可复现、成本敏感的场景用 Workflow。Agent 的价值在**输入不可预测**时。

**本项目**：`single` 模式就是「一个 Agent 内自主循环调工具」，而三层串并行的**层结构**是 Workflow（人定死），层内是 Agent。这是混合架构，可以这么讲。

---

### 2. ReAct 是什么？为什么有效？
**背**：Reasoning + Acting 交替循环：Thought → Action → Observation → Thought…
核心是**让模型看到工具返回的真实结果再决定下一步**，把「一步生成」变成「多步 grounded 生成」，减少幻觉。

**追问**：和 Chain-of-Thought 的区别？
→ CoT 只有推理没有外部反馈；ReAct 有 Observation，是**闭环**。

**本项目**：`crew.py:797 _run_agent_with_tools` 就是 ReAct 循环，`ReActStep` 数据类记录 thought/action/observation，`max_tool_rounds=3` 封顶。

---

### 3. Function Calling 的原理？
**背**：把工具的 JSON Schema 传给模型 → 模型返回「我要调 X，参数是 {…}」而不是自然语言 → 代码执行函数 → 把结果作为 `role=tool` 消息塞回对话 → 模型继续。
**关键点：模型不执行函数，只输出调用意图；执行在你自己的进程里。**

**追问**：模型怎么知道有哪些工具？（system/tools 字段传 schema）
参数瞎编怎么办？（Schema 约束 + `required` + 代码层校验 + 结果回传纠错）

**本项目**：`TOOLS` 列表（`crew.py:138`）7 个工具的 schema；`_normalize_tool_args`（`crew.py:403`）兜底参数名传错。

---

### 4. RAG 是什么？解决什么问题？
**背**：检索 + 生成。解决三件事：**知识过期**（模型训练截止）、**私有数据**（模型没见过）、**幻觉**（答案有出处）。
流程：切片 → 向量化 → 存向量库 → 查询时召回 top-k → 拼进 prompt → 生成。

**追问**：RAG 一定会减少幻觉吗？
→ 不一定。检索到**不相关**内容反而会误导模型（"distractor"问题）。所以要做重排、阈值过滤、引用标注。

**本项目**：28 城 JSON 切 chunk → bge-small-zh 向量化 → FAISS `IndexFlatIP`（内积=余弦，因已归一化）。

---

### 5. 稠密检索 vs 稀疏检索，为什么要用混合？
**背**：
- 稠密（向量/语义）：懂同义改写、泛化好，但**专有名词、精确匹配差**（"浅草寺" 可能召回成别的寺庙）
- 稀疏（BM25/TF-IDF）：精确匹配强、可解释、零训练，但**不懂语义**

混合 = 互补。融合要先**归一化**（两者量纲不同），再加权。

**追问**：BM25 相比 TF-IDF 好在哪？
→ 加了 **TF 饱和**（词频到一定程度不再线性加分，k1 控制）和 **文档长度归一**（长文档不占便宜，b 控制）。

**本项目**：`alpha=0.7` 语义 + `beta=0.3` BM25；BM25 除以最大值归一化；k1=1.5, b=0.75。

---

### 6. 什么是幻觉？Agent 里怎么治理？
**背**（分层答，显得体系化）：
1. **源头**：要求「只基于工具结果，没有就说暂无数据」（本项目每个 Agent 的 system prompt 都写了）
2. **过程**：ReAct 让模型看到真实 Observation
3. **事后**：自我反思/校验（本项目 `_self_reflect` + 输出格式校验）
4. **兜底**：关键字段强校验、引用溯源

**追问**：怎么量化幻觉率？
→ 构造带标准答案的 case，统计「工具没返回但模型写出来」的断言占比；或用 NLI 模型判 entailment。

---

### 7. 多 Agent 的协作模式有哪些？
**背**：
- **串行/Pipeline**：A 的输出是 B 的输入（有依赖）
- **并行/Fan-out**：子任务互不依赖，结果汇总
- **层级/Supervisor**：一个调度者分配任务
- **辩论/多评委**：多个模型产出，互相 critique
- **共享黑板**：所有 Agent 读写一个公共 context

**追问**：多 Agent 的代价？
→ **延迟 ×N、token ×N、错误会传播**（前序 Agent 错了，后序全错）、调试困难。
**这是必须主动说的**，光说好处会显得没做过。

**本项目**：L1→L2 串行（planner 依赖 researcher 成果），L3 并行（budget/foodie/safety 互不依赖）。

---

### 8. Agent 的记忆怎么做？
**背**（分两类）：
- **短期/会话内**：消息列表。问题是 context 膨胀 → 解法：滑动窗口、**摘要压缩**、工具结果裁剪
- **长期/跨会话**：向量库存 fact/preference，查询时语义召回注入

**追问**：怎么防「记忆污染」（存了错的/过期的）？
→ 加时间戳衰减、来源标记、冲突时按时间覆盖、允许用户删除。

**本项目**：短期 = messages 拼接 + 多轮超 10 条做 LLM 摘要；长期 = `memory.py` 向量记忆，Recall@3 87.5%。

---

### 9. 怎么评测一个 Agent？
**背**（分层）：
- **端到端**：任务成功率、LLM-as-judge 打分、人工抽检
- **过程**：工具调用准确率（选对工具 + 参数对）、工具成功率、平均轮次
- **工程**：P50/P95 延迟、token/成本、失败率
- **回归**：固定 case 集，改一版跑一次，看有没有退化

**追问**：LLM-as-judge 的偏差？
→ 位置偏差（偏好第一个）、长度偏差（偏好长的）、自我偏好（偏好自家模型）。
缓解：随机化顺序、多评委取平均、用 rubric 分维度打分、**人工抽检校准**。

**本项目**：`eval/eval_runner.py` 支持 `--ablation`；**失败 case 隔离**（0 次 LLM 调用/解析失败/全失败不计入均分），杜绝 0 分污染结论。

---

### 10. 工具调用失败怎么处理？
**背**：三级降级
1. **重试**（瞬时故障），带指数退避 + 抖动，防重试风暴
2. **降级/换工具**（fallback 链：知识库挂了 → 走搜索）
3. **优雅降级**（告诉模型「暂无数据」，让它跳过而不是编造）

**追问**：为什么重试要加**抖动**？
→ 大量请求同时失败会**同时重试**，形成重试风暴（thundering herd）。加 ±20% 随机抖动打散。

**本项目**：`_execute_tool_with_recovery`（`crew.py:515`）：重试 1 次 → `_TOOL_FALLBACKS` 链 → 降级文案。埋点区分 ok / ok_retry / ok_fallback / failed 四态。

## L1 · 高频（12 题，决定你能不能过二面）

### 11. 上下文窗口怎么管理？
滑窗 / 摘要 / 工具结果裁剪 / 结构化压缩。
**本项目**：多轮 >10 条时 LLM 摘要，保留最近 4 条原文；历史注入只取最近 3 条反馈。

### 12. 怎么控制 Agent 的成本？
- **模型分级**：简单分类/路由用小模型，生成用大模型（本项目路由用 `temperature=0.1, max_tokens=200` 的小调用）
- **缓存**：工具结果 TTL 缓存（本项目命中率 47.5%）
- **预算**：贵工具限次（本项目 web_search 限 2 次，超限降级本地）
- **早停**：轮次上限、token 上限
- **裁剪**：工具返回只取前 N 条

### 13. 什么是 Plan-and-Execute？和 ReAct 怎么选？
先让 LLM 生成完整计划，再逐步执行，可**动态重规划**。
ReAct 是走一步看一步（局部最优、可能跑偏）；Plan-and-Execute 是全局规划（前期成本高，适合长任务）。
**本项目**：偏向 ReAct + 人定的层结构（混合）。

### 14. 提示词怎么写才稳？
角色 → 工具使用策略（编号步骤）→ 输出格式（明确章节/字段）→ 约束（禁止编造、禁止输出 JSON/XML）→ 自检清单。
**本项目**：`agents.py` 每个 Agent 的 system 都是这个结构；反思 prompt 是「检查项 + 不满足就补，全满足回 PASS」。

### 15. 自我反思（Reflection）真的有用吗？
**诚实答**：学术界有 Refexion / Self-Refine 等，但**工业界收益不稳定**。
我的消融：开关反思得分完全一致（76.7），关掉快 30%。n=3 证据不强，但足以说明**没有可观测提升**。
→ **这种「我测了但没效果」的诚实回答非常加分。**

### 16. 向量库怎么选？FAISS / Milvus / pgvector？
- FAISS：库内嵌、单机、快，**适合 <百万级、无分布式需求**（本项目）
- Milvus/Qdrant：分布式、持久化、有过滤和元数据能力
- pgvector：已有 Postgres 就顺手用，省一个组件

### 17. Embedding 模型怎么选？
中文场景：`bge-small-zh`（快，本项目）、`bge-m3`（多语言+稀疏稠密一体）、`text2vec`。
选看：维度（存储/速度）、最大长度、领域是否微调过、是否支持**不对称检索**（query/doc 分开编码）。

### 18. chunk 怎么切？
固定长度 + overlap（通用）；按语义/标题切（结构化文档更好）；**小到大**（small-to-big，检索小 chunk、喂大上下文）。
坑：切太碎丢上下文，切太大引入噪声。

### 19. 召回后要重排吗？
要。向量召回是**近似**的，top-k 里混着噪声。
两阶段：快速召回（向量+BM25，top 50）→ **Rerank**（cross-encoder，top 5）。
**本项目没做 rerank**——被问到可以说「这是已知短板，下一步接 bge-reranker」。

### 20. Agent 怎么做可观测？
- **Trace**：每次 run 的树状结构（LLM 调用、工具调用、耗时、token）
- **指标**：工具成功率/降级率、P95 延迟、成本
- **日志**：ReAct 每一步的 thought/action/observation
工具：LangSmith（本项目可选接入）、Langfuse、自研埋点。
**本项目**：`tool_metrics.py` 旁路埋点（异常不影响主流程）+ `/api/metrics/tools` 实时查。

### 21. 限流怎么做？
令牌桶（控 RPS）+ 信号量（控并发）+ 指数退避带抖动（控重试）+ 队列超时。
**本项目**：`concurrency.py`，10 RPS / 并发 5 / 重试 3 次 / 退避 ±20% 抖动。

### 22. SSE 和 WebSocket 怎么选？
SSE：**单向**（服务端→客户端）、基于 HTTP、自动重连、实现简单，适合流式输出。
WebSocket：**双向**、需独立协议、适合实时交互（协同编辑、游戏）。
**本项目选 SSE**：只需推送 LLM 流；断线用 `after_id` 游标回放事件。

## L2 · 加分（8 题，答出来像资深）

### 23. 什么是 MCP？解决什么问题？
Model Context Protocol：Anthropic 提出的**工具/数据源接入标准**。
解决 M×N 集成问题：M 个应用 × N 个数据源各自写适配 → 统一成 M+N。
对比 Function Calling：FC 是「模型调函数的格式」，MCP 是「工具发现和供给的协议」，**两者是不同层**。

### 24. A2A / Agent 间通信协议？
Google 提出的 Agent-to-Agent 协议，解决**跨框架、跨组织的 Agent 互操作**（Agent Card 描述能力 + 任务生命周期）。
现状：早期，生产用的少，但**面试提一句说明你在跟进行业动态**。

### 25. LangChain / LlamaIndex / 手写，怎么选？
- 原型快 → LangChain；**生产我倾向手写核心循环**（本项目）
- 理由：黑盒难调试、版本 breaking change 多、抽象层掩盖了 token/延迟的真实来源
- 成熟做法：手写编排 + 只用它的**组件**（parser、splitter、向量库封装）

### 26. Agent 的安全风险？
- **Prompt Injection**：工具返回的内容里藏指令 → 隔离工具结果、权限分级、输出过滤
- **越权工具调用**：危险操作（删数据、付款）要人确认或白名单
- **数据泄露**：上下文里带了别的用户数据（多租户尤其致命）
**本项目**：safety Agent 被强制**禁止调 web_search**（安全信息必须来自知识库，防编造紧急电话）——这是安全设计的例子。

### 27. 长任务怎么做断点续跑 / 状态持久化？
把每个 Agent 的输出和中间事件**落库**，用 run_id 关联；失败从最后一个 checkpoint 恢复。
**本项目**：SSE 事件落 SQLite，thought/action/observation/agent_done/final 都存，token 不存（量大）。

### 28. 怎么做 Agent 的 A/B 和回归？
固定 case 集 + 固定评委 prompt + 多次运行取均值/方差；
**关键**：样本量要够（本项目 n=3 只能给方向性结论）、要报 σ、**失败 case 要隔离但也要列出**。

### 29. 什么时候该微调而不是改 prompt？
Prompt/RAG 解决**知识**问题；微调解决**格式稳定性、风格、领域分布**问题。
顺序：先 prompt → 再 RAG → 再 few-shot → 最后才微调（成本高、迭代慢）。
**坑**：用微调「记住」知识是错的，知识该走 RAG。

### 30. Agent 的延迟优化有哪些手段？
体感优化（骨架/流式/乐观渲染）、并行化、模型分级、缓存、裁剪上下文、轮次上限、关反思、提前终止。
**本项目**：骨架优先把「首屏可读」从 3 分钟压到 **803ms**——**先改体感再改真实延迟**，这是产品思维。

## 面试现场的三个「反杀」技巧

1. **被问「你的项目有什么亮点」** → 不要说功能，说**决策**。
   「我用消融证明了我自己的多 Agent 架构在这个场景不划算，默认改成了单 Agent。」比列十个功能强。

2. **被问「有什么不足」** → 说**真实的、你量化的**不足，然后说下一步。
   「消融 n=3，分差小于波动，所以我不宣称 single 更好；下一步是扩到 10 case 并加人工抽检。」

3. **被追问细节答不上来** → 不要编。
   「这块我没实测过，但我的判断是 X，因为 Y，要确认的话我会做 Z 实验。」
   编答案被抓 = 直接挂；诚实 + 给出验证路径 = 加分。
