# 演示脚本（90 秒）

面向面试/作品展示。全程用中文口述，控制在 90 秒内。

---

## 准备（演示前 10 分钟）

1. `.env` 填好 Key，服务已启动：`python -m uvicorn app.main:app --port 8000`
2. 浏览器打开 `http://localhost:8000`
3. 左栏确认：目的地东京、3 天、预算 1000、兴趣「文化,美食」
4. 执行模式：**多智能体（完整）**，勾选 **先出骨架**
5. 若网络不稳，备好：模式切「单智能体」+ 不勾骨架

---

## 口述 + 操作节奏

### 0–20 秒：一句话定位

> 「这是一个手写 Function Calling 的旅行规划系统。我重点解决两件事：用户不用白等，以及用消融回答多智能体到底值不值。」

点 **生成旅行方案**。

### 20–40 秒：骨架（体感）

看到右侧出现「⚡ 骨架预览」：

> 「不调大模型，本地知识库 + GPS 路线 + 线性规划预算，一秒内先给出可读骨架。Day 列表和预算区间已经能看。」

### 40–70 秒：Agent 填充（过程）

左侧 Agent 进度亮起，中间出现思考/工具调用：

> 「外层是三层：调研 → 规划 → 预算/美食/安全并行。每个角色用 Function Calling 调工具；web_search 有次数预算，超了就降级本地检索。」

若时间紧，可说：

> 「完整 multi 可能要几分钟，演示里我关反思会更快；产品上骨架保证用户始终有东西读。」

### 70–90 秒：收口（竞争力）

等 `final` 替换骨架后：

> 「同一套代码有 multi / sequential / single。我用 `--ablation` 同批评测比分差、耗时和粗估成本。多 Agent 分高就默认多；差不多就默认单——结论由数字定，不靠听起来高级。」

可选加分一句：

> 「知识图谱是 GPS 2.5 公里内真实邻近，不是列表相邻；BM25 是查询期 Okapi 公式。」

---

## 被打断时的短答

| 追问 | 30 秒答法 |
|------|-----------|
| 为什么不全并行？ | 规划依赖调研；预算/美食/安全互不依赖才并行。有 sequential 模式对照。 |
| 多 Agent 更好吗？ | 跑消融。分差明显就默认 multi，不明显就 single 更划算。 |
| 延迟多久？ | 完整 multi 数分钟；骨架秒出；single/关反思更快。 |
| 图谱是真的吗？ | 地理邻近 + 类型边，邻近用 Haversine≤2.5km，会返回公里数。 |

---

## 演示翻车预案

| 现象 | 处理 |
|------|------|
| 骨架没出来 | 刷新后只勾骨架、模式 single，先证明秒出 |
| Agent 卡住 | 展示左侧 thought/action，说明限流与重试；或切离线 fallback 叙事 |
| 输出像工具 JSON | 不硬讲内容，转讲「失败降级 + 评测会记 FAIL」 |
| 时间不够 | 在骨架出现后就收口消融故事 |
