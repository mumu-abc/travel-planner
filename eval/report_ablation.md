# 消融评测报告（multi vs single vs sequential × 反思开关）

- **日期**: 2026-09-15
- **模型**: mimo-v2.5-pro（全部样本同一模型，与 `eval/archive/` 历史报告一致）
- **用例**: T001 东京 / T002 巴黎 / T003 曼谷
- **评委**: 3 个 LLM 评委（完整性 / 实用性 / 结构化），取中位数 ×10

> 上一版报告（2026-09-13，n=1）中 sequential 与 multi-no-refl 两行出现「0.0 分却标记 ok」，
> 根因是评测器把离线降级与评委解析失败误计为成功样本。该问题已修复，
> 本次所有样本均通过 `status=ok` 校验（正常生成 + 评委可打分）。

## 关键结论

### 1. multi vs single：质量未见显著差异，但成本与稳定性差距明显

- 平均分差 **−3.3**（multi 76.7 vs single 80.0），**分差小于波动 σ=5.8**
- 因此**不能**说「single 质量更好」，只能说**质量至少相当**
- 在质量相当的前提下，single 全面占优：
  - 耗时 **202s vs 324s**（快约 1.6×）
  - 成本 **$0.0097 vs $0.0275**（省约 2.8×）
  - 波动 **σ=0 vs 5.8**（三次全部 80 分，结果稳定可预期）

→ **决策：产品默认档选 single**，multi 保留为「要五板块齐全」的深度档。
本质是**用数据否定了自己设计的多 Agent 架构**。

### 2. 反思机制：本测试未观测到质量收益，只带来延迟

- 开关反思的得分**完全一致**（均 76.7，且三个 case 逐个相同：70 / 80 / 80）
- 关闭反思后耗时从 324s 降到 226s（**快 30%**）
- 注意：n=3 且评分逐个重合，存在巧合可能；但至少可以确认
  「反思没有带来可观测的质量提升」

### 3. sequential 最差

- 去掉并行后耗时 471s（single 的 2.3 倍），成本最高，分数最低
- 印证：**并行的收益在延迟，不在质量**

### 4. 为什么 multi 反而不占优（深挖素材）

从逐次调用日志看，multi 的 LLM 调用 16.7 次 vs single 6.3 次：
- 多个 Agent 各自调工具，存在重复检索
- Agent 间输出传递会压缩上下文，前序 Agent 的细节会丢失
- 每个 Agent 独立触发「输出无效 → 强制重写」，放大 token 消耗

## 数据可靠性说明

- **样本量 n=3（sequential 为 2）**，属方向性结论，不足以支撑「显著差异」的断言
- 分差（3.3）小于波动（σ=5.8），严格统计意义上**未观察到显著差异**
- ~Token / ~成本为字符粗估，仅用于横向对比，不是账单
- 评委是 LLM-as-judge，存在主观偏差，正式结论应加人工抽检
- 本次跑批期间**外网不通**（DuckDuckGo / Wikipedia 全部 timed out），
  所有 web_search 均降级到本地知识库 `search_knowledge`；
  各配置受影响一致，横向对比仍然有效，但绝对分数偏低
- 全部样本使用同一模型 mimo-v2.5-pro
